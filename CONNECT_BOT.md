# ШАБАШКА: автоматическая публикация из Telegram

## Как работает после подключения

1. Разрешённый администратор пересылает вакансию в @shabashkanskbot.
2. Сервер проверяет секрет webhook и числовой Telegram ID отправителя.
3. Бот разбирает текст: название, категория, сумма и период оплаты, район, график, число людей, дата. Полное описание и контакты сохраняются без сочинённых деталей. Неопознанная профессия попадает в «Другое».
4. Запись сразу получает статус published. Ручное одобрение не требуется. Пересылка доверенным администратором является командой на публикацию.
5. Каталог берёт только published. В активной вкладке он обновляется каждые 45 секунд; есть и кнопка обновления. Ответ бота содержит ссылку на конкретную карточку.
6. Повтор текста либо исходного Telegram-сообщения не создаёт вторую запись. Кнопка «Снять с сайта» архивирует запись, «Вернуть на сайт» публикует её повторно.

Фото с подписью поддерживается; распознавания текста внутри фотографий нет. Если исходная публикация скрывает источник, оригинальная ссылка не выдумывается.

## Что уже проверено

29 автоматических тестов: разбор объявления, пересылка → published → публичная выдача, секрет webhook, проверка администратора, групповые сообщения, дубли, подпись фото, сохранность полного описания, ручной режим, снятие и восстановление, ошибка базы, относительные даты в Новосибирске. Интеграционные тесты используют тестовую базу в памяти; живой Telegram и облачная база не подключены.

## Что нужно для живого запуска

- Отдельная база SHABASHKA. Не использовать таблицы «Соседей», Road Live или других приложений.
- Node.js хостинг, исполняющий корневые api/ маршруты. В проекте подготовлена конфигурация Vercel. В приватной статической Sites-демонстрации эти маршруты не исполняются и webhook Telegram не работает.
- В новой базе выполнить sql/schema.sql. Если база уже использовала старую схему — sql/migrations/002_job_work_date.sql.
- В секретных настройках серверного хостинга установить TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET, TELEGRAM_ADMIN_IDS, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY; обычные серверные настройки TELEGRAM_BOT_USERNAME=shabashkanskbot, TELEGRAM_AUTO_PUBLISH=true, SITE_URL=https://ваш-живой-домен.
- Токен получать только у @BotFather и вводить в секретные настройки хостинга. Не отправлять его в переписку, git или публичный JavaScript. Числовой ID можно узнать командой /id у подключённого бота.
- Развернуть сервер с npm run build:production. В vercel.json это уже настроено. npm run build создаёт отдельное статическое демо и не является сборкой живого сервера.
- В доверенном терминале с заданными переменными выполнить npm run telegram:connect. Скрипт проверяет принадлежность токена именно @shabashkanskbot, регистрирует webhook и проверяет результат. Значения секретов не выводятся.

Режим TELEGRAM_AUTO_PUBLISH=false сохраняет импорт в pending с ручной публикацией. Это дополнительная настройка; по умолчанию включена автопубликация.

## Конечная проверка после настройки

Переслать реальную тестовую вакансию разрешённым аккаунтом → получить ответ «Опубликовано на сайте» → открыть ссылку → проверить категорию, оплату и описание → переслать повторно → убедиться, что дубля нет → снять вакансию кнопкой и проверить, что она пропала из каталога.
