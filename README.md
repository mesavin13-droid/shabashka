# ШАБАШКА

Работа и подработка в Новосибирске. Рабочий сайт: https://shabashka-nsk.vercel.app/

## Что работает

- Каталог вакансий с категориями, поиском, фильтрами и избранным.
- Пересылка администратором вакансии в @shabashkanskbot сразу публикует её на сайте. Сохраняются описание, контакты, оплата, район и график.
- Объявления остальных пользователей поступают на модерацию. Администратор получает кнопки публикации и отклонения.
- Повторы не создают новые карточки. Пересылка администратором вакансии, уже ожидающей модерации, публикует существующую запись.
- Вход на сайт через одноразовое подтверждение в боте. Сверяйте шестизначный код. Сессия действует 24 часа в текущей вкладке.
- Панель администратора: опубликованные, ожидающие проверки, снятые и отклонённые объявления; редактирование карточек, снятие и возврат на сайт.
- Нижнее меню на телефоне со скруглёнными углами и учётом safe area iPhone.

Веб-форма пока сохраняет личные черновики на устройстве. Публикация работодателем работает через Telegram-бота. Отклики, платежи и история смен не подключены.

## Архитектура

Статический интерфейс — HTML/CSS/JavaScript. Vercel собирает `dist/` командой `npm run build:production`. Фронтенд обращается к Supabase Edge Function `shabashka`; исходники обработчиков общие для Node и Deno. Текущая база и сервер уже подключены. Изменение интерфейса через GitHub не требует повторной настройки бота.

`PUBLIC_API_BASE` задаёт URL серверной функции при сборке. В репозитории указан адрес действующего сервера. Токен бота, секрет webhook и серверный ключ базы отсутствуют в исходниках. Действующие секреты находятся в Supabase Vault. RLS запрещает прямой доступ публичных клиентов к таблицам и закрытым RPC. Проверка администратора выполняется на сервере.

## Разработка и проверки

```sh
npm ci
npm test
npm run build:production
```

35 тестов проверяют разбор вакансий, повторную доставку, подписи авторизации, права администратора, очередь работодателей, редактирование и смену статусов. `npm run build` создаёт отдельную демонстрационную версию.

## Изменения сервера

После редактирования `api/`, `_lib/` или адаптера Edge Function:

```sh
npm run supabase:prepare
supabase functions deploy shabashka
```

Используется `supabase/config.toml`; функция сама проверяет Telegram webhook secret и пользовательские сессии. Не перезаписывайте действующие секреты при повторной публикации.

Для новой базы примените `sql/schema.sql`, затем миграции из `sql/migrations/`. Миграция 003 создаёт закрытую конфигурацию Vault, 004 — одноразовые запросы входа. Для нового бота настройте серверные переменные из `.env.example` и выполните `npm run telegram:connect` в защищённой среде. Никогда не добавляйте реальные секреты в Git или переменные браузера.
